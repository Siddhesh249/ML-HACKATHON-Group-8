# Experiment protocol

This document fixes the experimental contract so that every model, decoder and
report number is comparable and reproducible.

## 1. Partitions

| Partition | Trips | Permitted use |
|---|---|---|
| `train` | 80 | Fitting, GroupKFold(5), model selection, Bayesian optimisation, decoder tuning |
| `student_test` | 10 | Development-stage comparison of models and decoders |
| `evaluator_test` | 10 | Final evaluation only; never training/tuning/thresholds/feature choice |

Rules:

- Group all splits by **trip**. No observation from a trip may appear in two folds.
- Fit scalers, imputers and any learned preprocessing **inside** the training fold.
- Reproduce the split with the recorded seed and trip ID list.
- Never read `.route` in the prediction path.

## 2. Candidate and label contract

- Candidate generator: radius 60 m (fallback 100/150 m), top-K 15, arc samples every 5 m.
- Labels: monotonic route projection; low-confidence observations (>30 m from the
  assigned route segment) are excluded from fitting.
- Observations whose reference arc is missing from the candidate set are
  excluded from fitting and counted in the **candidate miss rate**.
- Feature order is `config.FEATURE_NAMES`; changing it requires re-exporting the
  artifact and bumping `FEATURE_VERSION`.

## 3. Model comparison

Train at least five distinct families. The minimum set in this repository is:

1. logistic regression (linear/probabilistic)
2. Gaussian Naive Bayes (probabilistic)
3. decision tree (tree)
4. random forest (ensemble)
5. Extra Trees (ensemble)
6. HistGradientBoosting (boosting)

Optional: shallow MLP, calibrated LinearSVC, nearest-road baseline.

For every model record:

- model name and family;
- important configuration / hyperparameters;
- CV macro F1, positive F1, precision, recall, log loss;
- CV observation Top-1 (fixed candidate sets);
- student-test metrics;
- training and inference time;
- evidence about over/underfitting.

**Primary selection metric:** CV observation Top-1. **Guardrails:** positive F1
and log loss. **Final gate:** decoder continuity and sequence F1 on student-test.

## 4. Cross-validation

- `GroupKFold(n_splits=5)` on the 80 training trips.
- Negative subsampling is applied **only to the fit set** (default 3 negatives
  per positive). Validation/test rows always use the full candidate set.
- Record `n_train`, `n_test`, fold trip IDs and per-fold metrics.
- Report mean and standard deviation across folds.

## 5. Metrics

| Metric | Definition |
|---|---|
| Candidate precision/recall/F1 | Binary metrics over candidate pairs; positive = reference arc |
| Macro F1 | Unweighted mean of positive and negative F1 |
| Log loss | Binary cross-entropy of calibrated candidate probabilities |
| Observation Top-1 | Per observation, argmax candidate equals the aligned reference arc; a missing truth counts as wrong |
| Candidate miss rate | Labelled observations whose reference arc is absent from the candidate set |
| Route continuity | Fraction of consecutive predicted arcs that are graph-connected (strict and relaxed) |
| LCS F1 | Order-aware precision/recall/F1 via the longest common subsequence of deduped arc sequences |
| Arc-set F1 | Set overlap of predicted and reference arcs |
| Inference time | Wall-clock per stage and per trip, same machine |

## 6. Bayesian optimisation

- Optuna TPE, group-aware CV over the 80 training trips.
- Objective: mean CV observation Top-1; tie-break with positive F1/log loss if
  the study needs a scalarised objective (document the choice).
- Record the search space, trial count, wall-clock cost, every trial including
  failures, best parameters and parameter importances.
- Refit the best configuration on all training trips, then compare tuned vs
  untuned on the same student-test trips.
- Never tune on evaluator data.

## 7. HMM tuning

- Tune `lam`, `sigma_m`, `beta_m`, `max_speed_mps`, `gap_reset_s`,
  `uturn_penalty` on training/student-test data only.
- Store the grid/study in `results/hmm/decoder_tuning.csv` and the chosen values
  in `artifacts/hmm_config.json`.
- Compare classifier-only and HMM with identical candidate sets and labels.

## 8. Result files

All results are CSV/JSON in `results/`, generated by scripts. Every row must
contain enough context to reproduce it:

```csv
run_id,git_commit,seed,partition,model,family,config,cv_top1,macro_f1,f1,log_loss,train_seconds,inference_ms,notes
```

Figures are generated from these files by scripts; no hand-drawn curves. Real
learning curves only for models that expose epoch-wise histories (MLP,
HistGradientBoosting); never invent training curves for tree models.

## 9. Artifact schema

`artifacts/model.joblib` is a dict:

```python
{
  "model": estimator,
  "feature_names": [...],
  "feature_version": "v1",
  "model_name": "...",
  "model_family": "...",
  "params": {...},
  "metrics": {...},
  "model_version": "sha256-prefix",
  "created_at": "...",
  "git_commit": "...",
  "config": {
      "use_graph_features": true,
      "candidate_radius_m": 60,
      "candidate_top_k": 15,
      ...
  }
}
```

The API refuses to load an artifact whose feature list differs from `config.py`.
`artifacts/hmm_config.json`, `feature_config.json` and `model_card.json` sit
next to it.

## 10. Reproducibility checklist

- Fixed seeds for splits, samplers and models.
- Record package versions (`pip freeze`) and the git commit.
- Record the dataset partition and trip IDs used.
- Do not overwrite previous results; add a new file/row.
- No data or secrets committed to git.
