# Technical report

Owner: **A** compiles; every member writes their own sections.

## Structure

See [`REPORT_OUTLINE.md`](REPORT_OUTLINE.md) for the mandatory sections, the
figures/tables each section needs, and the owner.

## Tools

Use whatever the team can edit together (LaTeX, Word, Google Docs), but the
final deliverable is **one PDF**. Keep the source in this folder:

```
report/
├── REPORT_OUTLINE.md
├── 02_data.md
├── 03_models.md
├── 04_optuna.md
├── 05_hmm.md
├── 07_deployment.md
├── figures/           (copied/generated from results/figures)
└── pathsnap_report.pdf
```

## Rules

- Every number must exist in `results/` and appear in the `viva.md` ledger.
- Every figure is generated by a script from real results; no hand-drawn curves.
- No fabricated metrics, maps, API logs or citations.
- Include the AI-assistance disclosure (see README §15).
- The PDF must match the public repository and the live demo.
- Do not submit separate reports per model.

## Final checks

- [ ] Required section order from the brief (2.2 → 7).
- [ ] All five+ models documented, with the required questions answered.
- [ ] Bayesian optimisation section with search space, objective, trials and best config.
- [ ] HMM section with states/emissions/transitions/gaps and classifier-vs-HMM comparison.
- [ ] Folium screenshots and committed HTML.
- [ ] API/UI screenshots and API log screenshot.
- [ ] Every figure has a caption and a source.
- [ ] Page numbers, table of contents, team contributions.
